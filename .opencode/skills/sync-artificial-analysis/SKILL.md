# 同步 Artificial Analysis Intelligence Index

## 范围与路径

- 只同步已有模型的 Artificial Analysis Intelligence Index 及其对应成本，不运行评测。
- 本 Skill 所在目录向上三级是数据仓库根目录，下文称 `DATA_ROOT`。先核对其中存在 `AGENTS.md`、`models/` 和 `benchmarks/`，不要依赖当前工作目录或写死用户的绝对路径。
- 先读 `DATA_ROOT/AGENTS.md`、README 中成绩、成本及构建规范，以及相关模型文件和现有 AA 定义。定义文件通常为 `benchmarks/artificial-analysis-intelligence-index-v5.toml`，实际内容是准据，不从文件名推断精确版本。
- 参考既有同步记录 `docs/artificial-analysis-sync-2026-11-07.md`（若存在），了解已核实来源和历史限制；历史记录不是当前版本或许可已获确认的证明。
- 本工作区的下载器通常在 `DATA_ROOT` 的父目录下：`scripts/download_artificial_analysis_scores.py`，快照在同一父目录的 `temp/`。独立检出数据仓库时这些文件可能不存在；应先检查，缺失时请用户提供快照或下载器位置，不自动添加工具、安装依赖或复制外部代码。
- 不默认新增模型、Benchmark 定义、映射数据库、导入脚本或定时任务，不修改其他评测、基本资料、描述、本地化及已有档位表示。
- 用户只要求预览时，不修改数据；用户明确要求同步时，先展示差异，再处理已核实项，不必为每个安全项重复确认。超出范围或无法核实的项目单独报告。

## 1. 确定输入

1. 检查数据仓库的 `git status --short`，记录已有改动，不覆盖或还原用户工作。
2. 用户指定快照时使用指定文件，不擅自换成别的快照。
3. 用户要求最新数据且下载器存在时，先阅读下载器及相邻 README，再运行下载。以下命令中的变量须先设置为核实后的实际路径：

   ```sh
   python3 "$WORKSPACE_ROOT/scripts/download_artificial_analysis_scores.py"
   ```

   以下载器实际输出的文件路径为准；同日重复下载可能产生 `-2` 等后缀，不猜测输出文件名。失败时报告，不悄悄用旧快照冒充最新数据。
4. 用户只要求使用本地最新快照时，检查候选文件名、修改时间和内容，明确报告所选文件；存在无法确定的先后或来源时询问用户。
5. 解析 TOML，记录输入路径、SHA-256、配置总数、有有效分数的数量、成本缺失与零值数量。分数和成本必须是有限数值且不是布尔值；零分可以是真实分数，不以真假值判断缺失。
6. 下载日期、文件修改时间和 `releaseDate` 都不是评测日期，不写入成绩 `date`；本任务也不更新模型发布日期。

## 2. 核对身份、版本和条件

当前下载器的简化快照只有 `name`、`releaseDate`、`intelligenceIndex`、`cost`，缺少配置标识、来源 URL、明确的档位和评测版本。**快照只能提供候选数值，不能单独证明完整的成绩身份。**

- 先扫描本地模型中 AA 成绩及其 `source`，利用已有官方模型页和历史核验线索建立本次匹配；名称相似、日期接近或分数相同均不能单独证明同一模型。
- 对新增和变更项核对 AA 官方模型页面；必要时查同一页面的原始数据，以确认配置标识（例如实际存在的 `slug`）、精确模型版本、来源和档位。不要从显示名称机械拼出 URL，也不要仅为取得更多字段擅自修改下载器。
- 一个本地模型可能对应多个 AA 配置和多个推理档位，逐条匹配、逐条保留，不取最高分。不同日期后缀、Preview、正式版或检查点不得未经核实合并。
- `effort` 只使用来源明确披露的原字符串，不从模型名括号猜测、不借用其他评测的 effort、不改大小写、不把缺失视作默认档位，不迁移已有 `variant`。
- 核对 AA 当前方法页、Index 定义及适用快照版本。不能把当前方法版本无条件套给旧快照，也不能把 5.0、5.0.1 或未来版本自动视作相同。
- 版本已核实但无本地定义时，可以保留用户要求范围内的原始成绩并报告未映射；不擅自新建或改写定义来消除警告。版本本身无法核实时跳过。
- 判重同时考虑模型 ID、评测名称、版本、指标、数据集、effort、variant、harness、source、date 及其他关键条件。成本字段不参与身份判重；缺失条件不证明条件相同。
- 无本地模型、多个可能映射或配置条件不明的条目跳过并说明，不能只按名称自动导入。

主要核验入口：

- https://artificialanalysis.ai/models
- https://artificialanalysis.ai/evaluations/artificial-analysis-intelligence-index
- https://artificialanalysis.ai/methodology/intelligence-benchmarking

## 3. 先输出差异

按以下类别汇总，列出有关的本地路径、AA 配置/来源、原值、新值及依据。先用快照做批量对比，只对新增、变化和歧义项深入查证，避免逐个重查所有未变化记录。

| 类别 | 默认处理 |
| --- | --- |
| 已匹配且数值不变 | 跳过，不重写 |
| 已核实的新配置成绩 | 添加一条完整记录 |
| 相同配置分数变化 | 核查是否官方修订；不能确认则保留本地并报告冲突 |
| 相同配置仅成本变化或缺成本 | 单独核实口径与来源，再补充或更新 |
| 来源中缺失分数/成本或不再出现 | 不清空、不删除本地数据 |
| 无法匹配、条件不足或版本不明 | 跳过，列出待核实原因 |

官方明确修正同一记录时可更新分数，并说明修订依据；不同实验条件应分别保留。不要无依据覆盖，也不要把同一条件的冲突数值另加一条来规避判重。

## 4. 成本规则

- Index 成本只取 `intelligenceIndexCostPerTask.cost.total`；现有简化快照的 `cost` 来自该路径，单位为 `USD/weighted task`。
- 不是 token 单价、总评测费用、`intelligenceIndexCost.total` 或某个组成评测的 `costPerTask`，不计算或换算替代值。
- `cost` 与 `cost_unit` 成对写入，原始精度保留；必要时提供独立的 `cost_source`，否则由该条成绩的 `source` 溯源。
- 只能将成本附到同一模型版本、档位、来源及已核实条件的成绩。相同分数不证明成本可以借用。
- 源数据为零或页面显示 `$0.00` 不足以证明真实零费用。零值未经核实则不导入成本，已有有效成本保持不变；负值、NaN、Infinity 和布尔值拒绝。
- 当前定价、缓存或成本口径可能变化。确认后更新当前观测成本时，在附近注释保留旧值、此次快照日期和依据；不声称旧值错误或当前值为评测当天账单，不推断重定价原因。

## 5. 最小化写入

- 只修改已确认的 `models/<lab>/<model-id>.toml` 中相关 `[[benchmarks]]`。
- 从原始数值写入，不主动四舍五入，不用网页展示整数替代已知高精度值。只有舍入展示值时，不能据此断言本地精确值已改变。
- 有明确来源时填写 `name`、`score`、`metric`、`version`、`source` 及已核实的条件；未知可选字段省略，不凭模板补值。
- 不整文件解析后重新序列化；保留无关字段、其他成绩、注释、顺序、已有精度和字段缺失状态。
- 仅新增或修改成绩不需要改描述和本地化。不手工编辑 `dist/`，需要产物时通过已有构建脚本生成。
- 用户没有要求时不提交、推送或发布。公开再分发前核查 AA 使用条款和数据许可；公开可下载或用户提供文件不等于获授权，Models.dev 的许可不覆盖 AA 数据。许可不明时明确报告，不代为认定已解决。

## 6. 校验与报告

修改模型后，在 `DATA_ROOT` 运行：

```sh
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
python3 scripts/build.py
git diff --check
```

- 先检查运行环境和仓库测试依赖；缺依赖或执行失败应报告，不声称通过，不擅自安装。
- 核对修改前后解析值，确认模型基本资料、其他评测和未计划变更的条件不变；修改的分数和成本与已核实输入一致。
- 检查重复、冲突、定义映射及新增警告，不将历史警告冒充本次新增问题，也不为了消除警告改写来源版本。
- `validate.py` 只检查 TOML 语法；构建和测试也不等于来源真实性、完整上游 Schema 或许可核验。
- 没有模型数据变化时，不为形式完整强行构建或重写文件；说明无变更及实际执行的检查。
- 最终简短报告：输入及摘要、修改的模型路径、新增/修正成绩数、补充/更新成本数、主要来源、实际校验结果、跳过项、冲突和许可限制。默认不额外创建报告文件；用户要求保存报告时再写入指定位置。
