# 采集与审核

## 范围与试点

当前只整理 LLM Benchmark 结果，不执行评测，不代理 Models.dev 目录或价格，不生成总榜及综合能力结论。

## 文件职责

| 文件 | 维护内容 |
| --- | --- |
| `data/benchmarks.json` | 标识、名称、版本、测量内容、类别、官方链接、指标、单位、方向与已知范围 |
| `data/sources.json` | 发布主体、固定出处、采集与发布日期、来源类型、许可和归属 |
| `data/model-mappings.json` | 来源原始名称与规范模型 ID 的对应证据 |
| `data/results/<benchmark-id>.json` | 原始分数、原文位置、配置、采集／评测日期与审核备注 |

Schema 对每种文档独立校验；跨文件检查全局 ID 唯一性、引用、分数范围和发布依赖。常用 JSON Schema 插件也可使用 `schemas/source-data.schema.json`。

## 状态与批准条件

所有实体都使用 `pending` / `approved` / `rejected`：

1. 收集时默认 `pending`。原文分数可以核对，但不代表模型映射和许可都已核实。
2. 定义批准前，核实正式名称、版本／修订边界、测量内容、指标单位及方向。范围只按指标定义设置；不能把所有成绩都限制成 0–100。
3. 来源批准前，核对 `redistribution: allowed` 的依据，记录许可名称、证据 URL、随附许可文件、归属和修改声明，检查附加 NOTICE。仓库代码许可不自动覆盖数据集、结果、模型输出或品牌素材。
4. 映射批准前，填写确切 `modelId`、证明模型身份／版本的 `evidenceUrl`、证明规范目录关联的 `catalogUrl` 及文字依据。脚本只检查证据字段存在，不联网验证链接内容，也不等于证据真实有效。
5. 成绩批准前，核对原文位置、原始数值、子集和配置，所有依赖都必须批准。已知但 v1 无法表达的重要条件必须阻止发布。
6. `approved` 表示经过维护者核实，不能仅因 AI 给出答案就批准。无效记录可标记 `rejected` 并保留原因，不静默换成猜测的模型或分数。

构建只选择已批准成绩；待审核和拒绝记录在报告中逐条列出。错误地批准了依赖未批准的成绩会直接失败，而不是静默跳过。

## 不可推断的信息

- 模型通用名不等于日期快照或别名；不自动进行模糊匹配。
- `evaluatedAt`、来源 `publishedAt`、`collectedAt` / `retrievedAt` 分别维护。只有来源明确的完整评测日期才进入当前客户端字段；日期部分已知时先写审核备注，不能补造日或时区。
- 未提到工具不等于禁用工具；未提推理等级不等于默认等级。
- `subset` 只记录已知子集，不用“full set”猜测覆盖范围。
- `cost` 可省略或为 null，明确的零不等于未知；仅保留来源可核实的原始费用值。币种、单位、总费用／平均费用等口径尚未统一，不套用 API token 单价、不自动换算或推算。真实费用填入前先核实语义及来源；已知但当前 v1 无法表达的重要费用条件应记录到 `unrepresentedConditions` 并阻止批准发布。现有三条试点成绩不补造费用。
- 多条结果不得按最高分覆盖。修正原记录的抄录错误保留 ID；新实验、新模型快照或不同配置用新 ID。
- 同一指标、同一单位不自动表示横向可比。当前不输出排名、比较组或复合分数。

## 下一项数据如何进入

优先选取来源可靠、规范 ID 可确认、许可明确、条件可表达且用户实际关心的少量模型。先闭环一项，再增加其他任务类别。只有人工录入成本确实增加时，才引入针对具体来源的导入脚本；导入结果仍须经过同一审核门禁，不接入自动批准／自动发布。
