# Models.dev 自动同步

[文档导航](README.md) · [待核实事项](review-notes.md)

## 运行与范围

`.github/workflows/sync-models.yml` 每小时第 17 分钟运行，也可手动触发。从 [Models.dev `dev/models`](https://github.com/anomalyco/models.dev/tree/dev/models) 拉取研发机构级数据，直接提交默认分支，不创建 PR。

需允许 `GITHUB_TOKEN` 写入仓库及机器人推送。推送被拒绝或分支并发更新时失败，不强推、不自动变基。

| 对象 | 行为 |
| --- | --- |
| 新模型 | 原样完整导入，包括上游成绩；本地缺少的历史模型也会补入 |
| 已有模型基本字段 | 跟随上游当前明确值更新或补充，不依赖旧上游基线 |
| 已有模型成绩 | 不更新、不补入、不重新校验或规范化；保留值、缺失状态、精度、格式与注释 |
| 本地补充及上游缺失字段 | 保留；字典逐字段合并，数组作为完整字段比较 |
| 已删除或重命名的上游模型 | 本地旧路径保留，新路径视为新模型；不判断别名 |
| Provider、Benchmark 定义、dist | 不同步 |
| 本地化 | 仅为本次新增模型追加中文译文，不自动补翻已有模型 |

同步不是永久人工字段锁定：上游明确提供同路径字段时仍可能覆盖本地基本信息（包括 metadata）。无法确认的兼容问题应报告，不自动合并。上游 MIT 声明保留在 [`LICENSE.models-dev`](../LICENSE.models-dev)；许可文本变化时停止同步等待审查，模型权重许可另行核实。

## 描述与翻译

- 已有模型的描述若有本地化条目，保留旧描述并报告，待人工同步原文和译文；其他基本字段可照常更新。
- 新模型保留上游原文，依次尝试 **Index-Translate → deep-translator（Google）→ Argos Translate**；首个通过检查的译文写入中文本地化，不覆盖已有条目。
- 全部翻译失败仍导入原文，摘要列出缺失项；后续人工补齐。自动检查不等于语义审核。

### 可选翻译后端

工作流仅在预览发现有效新模型时准备可选依赖，固定版本见工作流安装命令。缓存 Argos 英→中 1.9 语言包和 MiniSBD 英文断句资源，使用 CPU，避免 Stanza 启动时联网刷新。工作流总时限 30 分钟，三项准备各限 5 分钟；准备失败只禁用相应后端。

| 后端 | 一轮预算 | 单次超时 | 恢复处理 |
| --- | --- | --- | --- |
| Index | 4 分钟 | 120 秒 | 可恢复错误最多重试两次；429 遵循 Retry-After；截断时输出预算从 1024 提到 2048 重试一次 |
| Google | 2 分钟 | 20 秒 | 可恢复请求错误最多重试一次；子进程强制超时 |
| Argos | 2 分钟 | 30 秒 | 推理不重试 |

按后端分轮处理未成功项；持续网络错误、限流或不可用时可跳过后续调用。Index 使用免费 Chat Completions 接口与 Index-Translate-35B-A3B，关闭 thinking；Google 使用 `source=auto`、`target=zh-CN`，Argos 仅配置 `en→zh`。

Index 用标记保护模型名、数字、URL、代码及占位符；Google/Argos 接收自然原文，译后要求保留这些片段。空译文、原文照抄、缺少中文或保留项损坏转下一后端。公开描述可能发送给 Bilibili 和 Google，无需密钥；报告记录后端及失败原因，不记录第三方异常中的完整原文。

## 校验与写入保护

- 新模型检查 TOML、路径、Schema 标记、主要字段类型、成绩必填项、重复/冲突、URL 和定义映射。导入映射按名称、显式版本、指标匹配，允许定义声明的兼容版本，但不像构建器那样允许 `unspecified` 定义匹配缺省版本；不推断默认条件。未知字段或结构不兼容时跳过整个模型。
- 已有模型更新前检查本地、上游及合并后的基本字段；本地可暂缺尚未核实的能力或发行日期，但已提供值类型错误仍拒绝。上游候选及合并结果仍须通过完整导入检查，不填默认值。
- 用 `tomlkit` 精确编辑并独立确认成绩值和原始文本不变；无法安全编辑时跳过。例如末尾无换行会导致追加表与成绩粘连时，不为通过同步而修改成绩文本。
- 提交前只允许摘要列出的新增模型、基本信息更新和中文追加，逐一核对内容哈希；已有模型还核对更新前哈希与成绩文本。禁止额外文件、删除或重命名。
- 有实际数据更新才提交，提交信息记录上游 commit SHA。工作流名称需保持与 Pages 的 `workflow_run` 一致。

以上是保守导入检查，不是完整 Models.dev Schema 或联网真实性验证，也不自动新建评测定义、生成排行榜。检查实际变更及摘要中的跳过项，不能只看工作流成功。

## 本地预览

准备上游 Git checkout，报告建议写到仓库外：

```sh
python3 -m pip install tomlkit==0.13.3
python3 scripts/sync_models.py sync \
  --upstream /path/to/models.dev \
  --report /path/to/sync-report.json --dry-run
```

预览同时显示新增和基本字段变化，不需要旧上游基线。确认后移除 `--dry-run` 才写入；已有成绩始终不变。

本地默认不联网翻译，需 `--translate-descriptions` 显式启用；dry-run 即使配合该开关也只报告待翻译项。使用 Argos 前安装工作流所列可选依赖，并执行：

```sh
python3 scripts/translate_descriptions.py --prepare-argos
```

缓存位于 Argos 标准用户目录，可由 `ARGOS_PACKAGES_DIR`、`XDG_*` 调整。自动化预览和单元测试不下载语言包，基础同步、构建和测试也不依赖可选翻译后端。
